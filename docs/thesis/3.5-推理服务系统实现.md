3.5 推理服务系统实现

## 3.5.1 系统整体架构

本系统采用前后端分离架构，整体分为三层：前端交互层、后端服务层和数据持久层。各层职责如下：

（1）前端交互层：基于Vue3构建单页应用，部署于FastAPI静态文件服务。前端负责用户认证界面、图片上传、推理参数配置、结果可视化渲染以及历史记录查询等功能。组件化的设计使各功能模块独立维护，按需加载。

（2）后端服务层：基于FastAPI构建推理服务，以Uvicorn作为ASGI服务器运行在后端服务器上。模型推理采用同步调用方式，通过模型缓存机制避免重复加载。RESTful风格的API设计使前后端解耦，便于后续功能扩展。

（3）数据持久层：MySQL数据库存储用户信息、检测记录和模型配置，文件系统存储用户上传的模型权重文件和批量检测的标注结果图片。

## 3.5.2 后端服务架构

后端服务按功能可划分为四个模块：认证模块（Auth）、检测模块（Detections）、统计分析模块（Dashboard）和模型管理模块（Models）。

认证模块（`auth.py`）：提供用户注册（`/api/auth/register`）和登录（`/api/auth/login`）接口，采用JWT（JSON Web Token）机制实现无状态认证。用户注册时密码经bcrypt哈希后存入数据库；登录时验证密码后签发Token，客户端在后续请求中携带该Token，后端通过中间件验证Token有效性。

检测模块（`detections.py`）：提供单张检测（`/api/detections/predict`）和批量检测（`/api/detections/batch`）接口。单张检测流程：接收图片FormData → 校验图片格式 → 调用YOLO模型推理 → 结果与标注图片写入数据库 → 返回JSON响应。批量检测流程：接收多张图片 → 逐张推理 → 结果写入文件系统和数据库 → 返回汇总统计。模型通过`_MODEL_CACHE`缓存避免重复加载。

统计分析模块（`dashboard.py`）：提供统计数据接口（`/api/dashboard/stats`），返回累计检测次数、今日检测次数、过去7天每日检测趋势（by_day）以及过去7天缺陷类别分布（by_class），供前端仪表盘页图表展示。

模型管理模块（`models.py`）：提供模型列表查询（`GET /api/models`）、模型上传（`POST /api/models/upload`）和删除（`DELETE /api/models/{id}`）接口。用户上传的.pt权重文件存储于`experiments/uploaded_models/`目录，路径信息写入数据库。

## 3.5.3 数据库设计

系统数据库共包含三张表：用户表（users）、检测记录表（detection_records）和模型表（uploaded_models）。

用户表（users）：id（主键，自增）、username（用户名，唯一索引）、password_hash（bcrypt密码哈希）、created_at（注册时间）。

检测记录表（detection_records）：id（主键，自增）、user_id（外键，关联users.id）、filename（上传文件名）、model_name（模型名称）、conf（置信度阈值）、iou（IoU阈值）、num_detections（检测数量）、detections（JSON格式检测结果列表，含类别、置信度、边界框）、image_width、image_height（原始图像尺寸）、annotated_image_base64（标注图片Base64，批量模式置空以节省存储）、created_at（检测时间）。

模型表（uploaded_models）：id（主键，自增）、name（显示名称）、path（权重文件相对路径，唯一）、is_builtin（是否为内置模型）、uploaded_by（外键，关联users.id，可为空）、uploaded_at（上传时间）。

## 3.5.4 前端Vue3交互界面

前端按功能划分为四个页面：登录注册页、检测页、历史记录页和仪表盘页。

登录注册页（`LoginView.js`、`RegisterView.js`）：提供用户注册和登录表单，通过Axios调用后端认证接口。登录成功后Token存储于LocalStorage，后续请求通过Axios拦截器自动附加Authorization头。

检测页（`DetectView.js`）：核心功能页面。页面包含图片上传区（支持点击和拖拽）、推理参数配置区（置信度、IoU、输入尺寸、最大检测数）和模型选择下拉框。检测完成后以卡片形式展示每张图片的原始图、标注图和检测详情。

历史记录页（`HistoryView.js`）：以表格形式展示用户历史检测记录，支持分页查询、文件名搜索和模型名筛选。每条记录可点击查看详情，包括标注图片和完整检测结果。

仪表盘页（`DashboardView.js`）：调用`/api/dashboard/stats`获取统计数据，以折线图展示过去7天检测趋势，以柱状图展示缺陷类别分布，并展示累计和今日检测次数等指标。

前端路由：`/`→检测页，`/login`→登录页，`/register`→注册页，`/history`→历史记录页，`/dashboard`→仪表盘页。

## 3.5.5 API接口设计

系统所有接口均返回JSON格式数据。认证接口返回JWT Token，后续请求通过Authorization头携带。API接口文档通过Swagger UI自动生成（`/docs`）。

主要接口汇总：

| 接口路径 | 方法 | 功能 | 认证 |
|---------|------|------|------|
| /api/auth/register | POST | 用户注册 | 否 |
| /api/auth/login | POST | 用户登录 | 否 |
| /api/detections/predict | POST | 单张图片检测 | 是 |
| /api/detections/batch | POST | 批量图片检测 | 是 |
| /api/detections | GET | 历史记录查询（分页+筛选） | 是 |
| /api/detections/{id} | GET | 记录详情 | 是 |
| /api/detections/clear | DELETE | 清空历史记录 | 是 |
| /api/dashboard/stats | GET | 统计数据 | 是 |
| /api/models | GET | 模型列表查询 | 是 |
| /api/models/upload | POST | 模型文件上传 | 是 |
| /api/models/{id} | DELETE | 删除模型 | 是 |
