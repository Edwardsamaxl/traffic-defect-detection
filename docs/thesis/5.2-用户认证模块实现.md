## 5.2 用户认证模块实现

用户认证模块用于完成系统的身份识别和接口访问控制，主要包括登录注册页面、后端认证接口、用户模型、JWT 令牌生成与校验逻辑。系统采用前后端分离的实现方式，前端负责收集用户名和密码、保存登录状态并在后续请求中携带 Token；后端负责校验用户身份、签发 Token，并在业务接口执行前判断请求是否合法。

登录页面实现效果如图 5-X 所示。页面由 Vue 组件 `LoginView.js` 实现，整体采用左右分栏布局，左侧展示系统名称 Traffic Defect Detection 和系统说明，右侧为用户名、密码输入框和登录按钮。用户输入账号后，前端调用 `auth.js` 中的 `login` 方法，请求后端 `/api/auth/login` 接口。若登录失败，页面会显示后端返回的错误信息；若登录成功，前端将返回的用户信息和 Token 分别保存到 `localStorage` 的 `user` 和 `token` 字段中，并跳转到系统主页面。注册页由 `RegisterView.js` 实现，页面结构与登录页保持一致，只是在前端增加了确认密码校验，提交后调用 `/api/auth/register` 接口创建新用户。

用户认证模块的核心结构如图 5-X 所示。图中的 `User` 对应后端 `models/user.py` 中的用户实体类，该类通过 SQLAlchemy 映射数据库中的 `users` 表，包含 `id`、`username`、`password_hash` 和 `created_at` 字段。其中 `username` 设置唯一索引，用于避免重复注册；`password_hash` 只保存密码哈希值，不保存明文密码。`User` 类还提供 `set_password` 和 `verify_password` 两个方法，分别用于生成密码哈希和校验登录密码。密码处理通过 passlib 的 `CryptContext` 完成，当前配置使用 bcrypt 算法。

图中的 `AuthService` 是对认证服务逻辑的抽象，在代码中主要由 `api/auth.py` 实现。该文件使用 FastAPI 的 `APIRouter` 定义认证路由，统一挂载在 `/api/auth` 路径下。注册接口接收 `RegisterRequest`，先检查用户名长度是否不少于 3 个字符、密码长度是否不少于 6 个字符，再查询数据库判断用户名是否已经存在。校验通过后，后端创建 `User` 对象，调用 `set_password` 写入密码哈希，并提交数据库事务。登录接口接收 `LoginRequest`，根据用户名查询用户记录，再调用 `verify_password` 与数据库中的哈希值进行比对。注册和登录成功后，后端都会调用 `create_access_token` 生成 JWT，并将 Token 与用户信息一起返回给前端。

JWT 的签发与解析使用 `python-jose` 完成，密钥和算法配置位于 `config.py`。系统使用 HS256 作为签名算法，Token 载荷中写入 `sub` 和 `exp` 两个主要字段，其中 `sub` 保存用户 ID，`exp` 表示过期时间。当前实现中 Token 有效期为 1440 分钟，即 24 小时。由于 Token 中只保存用户标识和过期时间，后端不需要维护会话状态，接口收到请求后只需校验签名、解析用户 ID，再查询数据库确认用户仍然存在。

认证模块的数据流如图 5-X 所示。用户注册或登录时，前端向认证接口提交用户名和密码；后端完成 bcrypt 密码校验后签发 JWT；前端收到响应后保存 Token。之后用户访问检测、历史记录、仪表盘、模型管理等页面时，前端路由守卫会先检查本地是否存在 Token。没有 Token 的用户会被重定向到登录页，已经登录的用户则可以进入受保护页面。

在接口请求层面，`static/js/api/client.js` 创建了统一的 Axios 实例，并在请求拦截器中读取 `localStorage` 中的 Token，自动添加 `Authorization: Bearer <token>` 请求头。后端受保护接口通过 `Depends(get_current_user)` 声明依赖，由 `middleware/auth.py` 中的 `get_current_user` 函数完成 Token 校验。该函数使用 `HTTPBearer` 从请求头中取出 Token，调用 `jwt.decode` 验证签名和有效期，随后从载荷中的 `sub` 字段获取用户 ID 并查询数据库。如果 Token 无效、已过期，或数据库中不存在对应用户，接口会返回 401 状态码。

这种实现方式把认证逻辑集中在认证路由和认证中间件中，业务接口只需要声明当前用户依赖即可获得用户身份。例如检测接口、历史记录接口、模型管理接口和仪表盘接口都使用 `current_user: User = Depends(get_current_user)` 获取当前用户。这样既减少了重复代码，也能保证不同业务模块使用同一套鉴权规则。前端在收到 401 响应时会清除本地 Token 和用户信息，并跳转回登录页，使登录状态失效后的处理过程保持一致。
